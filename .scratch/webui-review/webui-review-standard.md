# Token Analyzer WebUI 显示审查标准

> 适用范围：`token-analyzer serve` 提供的单页前端（src/webui.html）+ `/api/*` 后端契约。
> 审查对象：运行实例 http://127.0.0.1:50080/（数据目录 `~/.pi/agent/sessions`，231 会话）。
> 审查方法：静态代码走查（webui.html / api.ts）+ 真实浏览器交互验证（agent-browser）+ 接口响应核对（curl）。

## 0. 缺陷分级

| 级别 | 定义 | 判定 |
|---|---|---|
| **P0 阻断** | 页面不可用、数据错误导致误导、功能完全失效 | 必须修复 |
| **P1 严重** | 明确的功能性 bug，但存在绕过路径或影响面局部 | 应修复 |
| **P2 一般** | 显示瑕疵、边界行为不当、易用性问题 | 建议修复 |
| **P3 轻微** | 风格/一致性/死代码等打磨项 | 可选 |

每条发现记录：`[级别] 位置 / 现象 / 复现步骤 / 预期行为 / 依据（标准条款）`。

## 1. 布局与信息架构

| ID | 检查项 | 通过标准 |
|---|---|---|
| L-1 | 顶栏标题与四个 tab（总览/会话明细/请求明细/会话管理） | 全部可见、当前 tab 高亮、点击切换内容 |
| L-2 | 工具栏（时间预设、自定义范围、自动刷新、刷新按钮） | 完整呈现、控件可交互 |
| L-3 | 状态行（数据目录/会话数/范围） | 存在且信息与 meta 接口一致 |
| L-4 | 总览卡片区（请求数/输入/输出/缓存/推理/缓存率/总token/花费） | 8 张卡片齐全、值可读、无「-」残留 |
| L-5 | 分组表（按模型/按 cwd）与导出按钮 | 存在、可切换、表头列与数据列对应 |
| L-6 | 明细表 + 分页器（每页行数/上一页/页码信息/下一页） | 存在且对齐；长表横向滚动不破版 |
| L-7 | 会话管理分组（按 cwd 折叠组、会话行） | 分组正确、可折叠、行内信息完整 |
| L-8 | 响应式 | 窗口缩放（≥1280 / ~900 / 移动宽度）不破版、不溢出 |

## 2. 数据正确性

| ID | 检查项 | 通过标准 |
|---|---|---|
| D-1 | 卡片数值与 `/api/totals` 一致 | 逐项核对（请求数/输入/输出/缓存/推理/缓存率/总token/花费）；输出=output+reasoning、缓存=cacheRead+cacheWrite |
| D-2 | 未定价显示 | cost=0 时显示「费率未配置（免费/未定价）」而非 0 |
| D-3 | 分组表与 `/api/groups?by=model|cwd` 一致 | 分组键、请求数、各 token 列、缓存率、花费逐行核对；键列为原始字符串 |
| D-4 | 会话明细与 `/api/sessions` 一致 | 列（名称/ID/时间/cwd/模型/请求数/输入/输出/缓存率/总token/花费）与接口字段对应，total 与行数相符 |
| D-5 | 请求明细与 `/api/requests` 一致 | 列（名称/ID/时间/模型/输入/输出/缓存/推理/缓存率/总token/花费）；缓存列=cacheRead+cacheWrite |
| D-6 | 会话管理显示名 | 与 `/api/sessions` 的 displayName 一致；重命名过的用文件名前缀，未重命名用首条 user 消息 |
| D-7 | 会话数/数据范围 | 状态行会话数与 meta.sessionCount 一致；范围与 meta.dataRange 一致 |
| D-8 | 数字格式化 | 千分位、k/M 缩写（≥1e4 用 k、≥1e6 用 M）、百分比两位小数、花费 6 位小数 |
| D-9 | 空态 | 筛选后无数据时表格显示空（不残留旧行、不报错） |

## 3. 交互与状态

| ID | 检查项 | 通过标准 |
|---|---|---|
| I-1 | tab 切换 | 无整页刷新；切换即拉取对应端点；非当前 tab 不重复请求 |
| I-2 | 时间预设（今天/7天/30天/全部/自定义） | 按钮 active 状态正确；today=本地当日 00:00~23:59:59；7d=含当天往前 7 天；30d 同理；全部=无筛选 |
| I-3 | 自定义范围 | 日期+时分 6 控件组合正确；只有日期=纯日期全天；仅设 since 或 until 生效；输入即生效 |
| I-4 | 状态行范围联动 | 筛选时显示当前筛选范围（纯日期补 00:00/23:59:59）；未筛选显示全量数据范围 |
| I-5 | 明细排序 | 点击表头：首次 asc、再点 desc、箭头 ▲/▼ 正确；排序后回到第 1 页 |
| I-6 | 明细分页 | 上一页/下一页边界禁用正确；页码信息「N 行 · 第 X/Y 页」正确；改每页行数回到第 1 页 |
| I-7 | 刷新按钮 | 立即重拉当前 tab 数据 |
| I-8 | 自动刷新 | Off/5s/30s/5min 生效；数据变化时状态行显示「已更新 HH:MM:SS」；无变化不闪烁 |
| I-9 | 导出 JSON/CSV | 文件可下载、内容结构完整（totals/sessions/requests 三段）、随当前时间筛选 |
| I-10 | 会话重命名 | 点击名称→行内编辑；Enter 保存/失焦保存/Esc 取消；重名/活跃/非法名错误提示；成功刷新分组；一次只编辑一行 |
| I-11 | 竞态 | 快速切换 tab/排序/翻页不出现旧数据覆盖新数据、不抛未捕获异常 |

## 4. 时间语义

| ID | 检查项 | 通过标准 |
|---|---|---|
| T-1 | 时间戳显示 | 全部为本地时间（YYYY-MM-DD HH:MM:SS）；非法时间戳原样回退不崩溃 |
| T-2 | 筛选口径 | 明细/卡片按消息级时间过滤（跨天会话凌晨请求计入当天）；会话明细/管理按会话 header 归属 |
| T-3 | 预设边界 | 「今天」能取到当日凌晨与深夜消息；跨天会话部分请求被保留时 total 与筛选结果一致 |
| T-4 | 状态行范围显示 | 纯日期筛选补全 00:00 / 23:59:59；自定义时间戳去 T 显示 |

## 5. 视觉与可读性

| ID | 检查项 | 通过标准 |
|---|---|---|
| V-1 | 暗色主题一致性 | 背景/面板/边框/文字/强调色统一；无白底刺眼区域 |
| V-2 | 数字对齐 | 数值列右对齐、首列左对齐、tabular-nums 等宽数字 |
| V-3 | 长内容截断 | 会话名/ID/cwd 超宽省略号或横向滚动，不撑破表格 |
| V-4 | hover/active 状态 | 表头、行、按钮、tab 有清晰的 hover/active 反馈 |
| V-5 | 状态行/错误横幅 | 加载中→完成无闪烁；错误横幅出现时可见且不遮挡操作 |

## 6. 错误处理与健壮性

| ID | 检查项 | 通过标准 |
|---|---|---|
| E-1 | API 失败 | 错误横幅显示接口 detail，页面不白屏、不无限 loading |
| E-2 | 非法参数 | 服务端非法 page/size/sortKey/sortDir/since/until → 400 统一错误体 |
| E-3 | 空数据目录 | 500 统一错误体；前端显示错误横幅 |
| E-4 | 控制台 | 无未捕获异常、无资源加载错误、无 CSP 违规 |

## 7. 安全

| ID | 检查项 | 通过标准 |
|---|---|---|
| S-1 | 输出转义 | 所有注入 innerHTML 的动态字符串（会话名/分组键/model/cwd/错误信息）均经 escapeHtml；无 XSS 注入点 |
| S-2 | 重命名输入净化 | 非法文件名字符（/ \ : * ? " < > |）被剔除；空名被拒 |
| S-3 | 无敏感信息泄漏 | 页面/接口不暴露 token、密钥、私有路径之外的信息 |

## 8. 性能

| ID | 检查项 | 通过标准 |
|---|---|---|
| P-1 | 明细分页生效 | 明细端点只传输当前页（page/size 参数），非全量 |
| P-2 | 首屏加载 | 页面加载与首次数据渲染在合理时间（≤2s）内完成 |
| P-3 | 轮询开销 | 自动刷新周期内请求数合理；明细 tab 轮询只对比当前页+total，不拉全量 |
| P-4 | 导出开销 | 导出文件大小合理可下载，不阻塞 UI 超时 |

## 9. 代码质量（静态走查）

| ID | 检查项 | 通过标准 |
|---|---|---|
| C-1 | 无死代码/无效属性 | 无未使用函数、无 `data-sort`/`data-dir` 等无效属性残留 |
| C-2 | 状态一致性 | state（since/until/groupBy/tab）与 DOM 控件（active 类/控件值）同步 |
| C-3 | 重复请求 | 单次操作不触发重复/冗余 API 请求（轮询对比后变化才刷新） |
| C-4 | 错误路径 | async 函数均有 catch；错误信息对用户可读 |

## 10. 记录格式

审查报告按维度组织，每条发现含：

```
[级别 P0/P1/P2/P3] 检查项ID
- 位置：文件/组件/接口
- 现象：实际行为（附截图/接口响应证据）
- 复现：操作步骤
- 预期：标准要求的行为
- 影响：对用户的实际影响
```

报告结尾附：审查环境（浏览器/日期）、总体结论、按级别统计、修复建议优先级。
