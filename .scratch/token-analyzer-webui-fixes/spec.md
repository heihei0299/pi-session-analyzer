# Token Analyzer WebUI — 审查问题修复规格（Spec）

**状态**: ready-for-agent（本 spec 由 grill-to-spec 综合 webui 审查结论产出：.scratch/webui-review/webui-review-standard.md + webui-review-report.md，供后续 session 按此实现修复）

**前置**: 依赖 token-analyzer-webui 既有实现（单 HTML 内联前端 + 零依赖 HTTP 服务 + /api/* 端点）。审查针对运行实例 http://127.0.0.1:50080/（数据目录 ~/.pi/agent/sessions）完成；报告 9 项发现（3 P2 + 6 P3），本 spec 覆盖全部 9 项。数据域与统计口径见 `.scratch/token-analyzer/spec.md`，webui 功能规格见 `.scratch/token-analyzer-webui/spec.md`。

---

## Problem Statement

webui 经系统审查（标准 + 报告见 `.scratch/webui-review/`）确认主体功能正确，但存在 9 项显示与正确性问题：

- **P2（正确性）**：① 非法日历日期（如 2026-02-30、2026-07-32）被 JS Date 静默归一化，时间筛选范围错位且 400 校验失效；② 会话重命名按 Esc 取消且输入为空时误报「显示名不能为空」；③ 总览分组表的分组键列（model 名 / cwd 路径）未做 HTML 转义，是全页唯一注入点。
- **P3（显示/体验）**：④ 超 10 亿的数字仍以 M 显示（如 1415.6M）可读性差；⑤ 导出全量数据（约 28MB 原始 JSON）无任何进行中反馈；⑥ 请求明细表头残留无效 data-sort/data-dir 属性；⑦ 自动刷新轮询在总览下每周期最多发 5 个请求（其中 totals/groups 重复）；⑧ 「自定义」预设未填值时数据=全部但按钮高亮，语义模糊；⑨ 应用时间筛选后状态行「会话数」仍显示全量，与筛选结果口径不一致。

用户需要：这 9 项问题得到修复，使页面显示正确、反馈清晰、口径一致，且不改变既有功能行为。

## Solution

在既有 webui 展示层与共享参数解析层做局部修复，全部问题收敛为三类动作：**严格参数校验**（P2-1）、**前端渲染与交互修正**（P2-2/P2-3/P3-1/P3-3/P3-5）、**反馈与请求优化**（P3-2/P3-4/P3-6）。不新增功能、不重写模块、不改变统计口径：

- 非法日历日期（纯日期参数）一律拒绝：CLI 与 API 共享的日期解析器对「不存在于公历的日期」抛错；API 转 400 统一错误体，CLI 报错退出（exit 1）。
- 会话重命名取消逻辑与空名校验分离：Esc/取消永不显示错误；仅「保存但名称为空」显示「显示名不能为空」。
- 分组表分组键列与其他动态字符串同样经 HTML 转义渲染。
- 数字格式化补十亿档；导出按钮在导出期间显示「导出中…」并禁用；「自定义」预设预填当前生效范围；状态行在筛选时显示「筛选后（全量）」双值会话数；自动刷新变化时复用已拉取数据渲染，消除重复请求；删除无效表头属性。

## User Stories

1. As a webui 用户, I want 通过 URL 直接构造非法日期（如 since=2026-02-30）时得到明确的 400 错误，so that 我不会在静默错位的筛选范围下看到误导数据。
2. As a CLI 用户, I want 传入非法 --since/--until 日期时命令报错退出（而非静默按归一化日期统计），so that 我能立即发现参数错误而非得到错误结果。
3. As a webui 用户, I want 行内编辑会话名时按 Esc 取消不出现任何错误提示，so that 取消操作与失败操作可区分。
4. As a webui 用户, I want 分组表中包含 `&`、`<` 等字符的 model 名/cwd 路径正确显示（而非被当作 HTML 解析），so that 任何数据都不会破坏页面渲染或产生注入风险。
5. As a webui 用户, I want 超过 10 亿的 token/缓存数值以 B 单位显示（如 1.4B），so that 大数字一眼可读。
6. As a webui 用户, I want 点击导出后按钮变为「导出中…」并禁用直到完成，so that 我知道导出在进行中，不会重复点击。
7. As a 开发者, I want 删除请求明细表头中无效的 data-sort/data-dir 属性，so that 前端代码无死残留、结构语义清晰。
8. As a webui 用户, I want 自动刷新在总览页每周期只拉取必要的 totals+groups，so that 轮询开销最小化、服务器压力降低。
9. As a webui 用户, I want 点击「自定义」时时间控件预填当前生效范围（或全量数据范围），so that 我能直接微调而非面对空控件。
10. As a webui 用户, I want 应用时间筛选后状态行显示「会话数: N（全量 M）」，so that 筛选口径清晰、不误解筛选结果规模。
11. As a 回归测试者, I want 上述修复有自动化测试覆盖（服务端 400/抛错、前端 HTML 转义与结构），so that 修复不回归。

## Implementation Decisions

1. **P2-1 严格日期校验（parseTimestamp 全局）**：纯日期分支在 `new Date(y, mo-1, d)` 构造后回读 `getFullYear/getMonth/getDate` 与输入比对，不一致即抛错（JS Date 对溢出日期自动归一化，如 2026-07-32 → 2026-08-01，须显式拒绝）。CLI 与 API 共享此解析器：API 经既有 try/catch 映射为 400 统一错误体；CLI 走既有入口错误路径（stderr 输出 + exitCode 1）。完整时间戳分支保持现有 `Date.parse` 行为（非法即抛错）。此决策使 CLI 与 API 语义一致——避免「CLI 归一化、API 拒绝」的双轨。

2. **P2-2 取消与空名分离**：行内编辑的退出处理拆为两个独立分支——`!save`（Esc 取消/失焦不保存）直接恢复原名称且**不写任何错误**；`!name`（保存但名称为空）才显示「显示名不能为空」并恢复。Enter 保存路径、Esc 取消路径、失焦语义均保持既有行为。

3. **P2-3 分组键转义（防御性渲染）**：通用表格渲染器对**非格式化列**（无格式化函数、原始字符串）统一经 HTML 转义输出；总览分组表的分组键列（model 名 / cwd 路径）随之获得转义。明细表与会话管理已有的逐列转义保持不变，不做重复转义。

4. **P3-1 十亿单位**：紧凑数字格式化增加 `≥ 1e9 → B` 档（1 位小数、去尾 0），与既有 `k`/`M` 档同风格；1e4 以下保持千分位。

5. **P3-2 导出中状态**：导出触发后按钮文案切换为「导出中…」并禁用（JSON 与 CSV 两个按钮同时禁用），三个接口的 Promise.all 完成后恢复；失败恢复并走既有错误横幅路径。不做导出大小预估或确认对话框。

6. **P3-3 死属性清理**：请求明细表头移除从未被脚本读取的 `data-sort`/`data-dir` 静态属性（默认排序状态已由前端状态对象承载）。

7. **P3-4 轮询复用快照数据**：自动刷新轮询检测到变化后，**直接用本轮 snapshot 已拉取的数据渲染**，不再整刷刷新入口：总览页用快照的 totals/groups 渲染卡片与分组表（meta 仍单独拉取以更新状态行）；明细页沿用「只对比当前页+total、变化后渲染当前页」的既有语义。每周期请求收敛到 totals+groups+meta 的最小集合，消除重复。

8. **P3-5 自定义预填**：点击「自定义」预设时，将当前生效的 since/until 值填入 6 个时间控件（日期 + 时分下拉拆分）；无生效筛选（全部）时预填全量数据范围（元数据 dataRange）的本地日期。预填后控件输入即生效的既有行为不变。

9. **P3-6 状态行双值会话数**：存在时间筛选时状态行显示「会话数: N（全量 M）」——N 取会话明细分页响应的 total（筛选后会话数），M 取元数据 sessionCount（全量）；未筛选时保持单值 M。N 的获取复用明细端点既有分页响应字段，不新增接口。

## Testing Decisions

- **测试原则**：只测外部行为——API 状态码与错误体、CLI 退出码与 stderr、前端 HTML 输出结构；不测实现细节（不回读函数内部、不断言私有状态）。
- **服务端（prior art：`07-api.test.ts` 的 fixture + 随机端口 serve + fetch 断言错误体；`04-s1-since-until.test.ts` 的时间筛选语义）**：
  - `parseTimestamp` 对非法日历日期（2026-02-30 / 2026-07-32 / 2026-13-99 / 2026-00-10 / 2026-08-32）抛错，合法日期（含闰年 2024-02-29、月末 2026-08-31）正常解析；
  - `/api/totals|requests|sessions|groups` 携带非法 since/until → 400 且错误体含「无效 since/until」；
  - CLI `--since 2026-02-30` → 退出码非 0 且 stderr 非空；合法日期行为不变。
- **前端（prior art：`09-detail-views-ui.test.ts` 的 HTML 结构断言）**：
  - 分组表 HTML 中，含 `&`/`<` 的 model 名/cwd 输出为 `&amp;`/`&lt;`（转义断言）；
  - 请求明细表头不再含 `data-sort`/`data-dir` 属性；
  - 导出按钮在导出期间 disabled 与「导出中…」文案（结构层面可断言的部分）。
  - 交互行为（Esc 取消不报错、B 单位、自定义预填、状态行双值、轮询复用）延续既有「交互按 spec 手工验收」的约定，辅以审查标准 V/I/T 条目回归走查。

## Out of Scope

- 除 9 项修复外的任何 webui 新功能（时间趋势图、多窗口对比等）。
- 导出性能重构（流式/分页/增量导出）——本次仅加导出中状态提示，全量导出限制维持现状。
- 前端 jsdom / 浏览器自动化测试基建搭建（手工验收约定保持）。
- 既有 `.scratch/token-analyzer-webui/spec.md` 功能规格的未决项与实现收尾（另 issue 追踪）。
- 审查标准/报告的更新维护（二者为审查产物，已落盘 `.scratch/webui-review/`）。
